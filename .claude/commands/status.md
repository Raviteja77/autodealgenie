# /status — Project Status Briefing

Load: @.claude/memory/PROGRESS.md
Load: @.claude/memory/DECISIONS.md

Give a clear, human-friendly project status briefing covering:

1. **What phase are we in?** (Redesign / Feature build / Stabilization / etc.)
2. **What's done?** (Backend services + Frontend pages — their current state)
3. **What's in progress?** (Current active work)
4. **What's next?** (Recommended next 1-3 tasks, in priority order)
5. **Open questions** (Decisions that still need to be made)
6. **Known issues** (From GOTCHAS.md that haven't been fixed yet)

Write this in plain English. Imagine explaining the project status to someone
who hasn't worked on it in a week. No jargon without explanation.

After the briefing, ask: "Which of these should we work on next?"
